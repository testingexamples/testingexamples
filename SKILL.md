# Playwright C# Skill

## What Playwright for .NET is

Playwright (https://playwright.dev/dotnet/) drives Chromium, Firefox, and WebKit through one API. The .NET binding is the `Microsoft.Playwright` NuGet package; `Microsoft.Playwright.NUnit` and `Microsoft.Playwright.MSTest` add test-framework base classes.

```sh
# Test project (recommended for real tests):
dotnet new nunit -n PlaywrightTests
cd PlaywrightTests
dotnet add package Microsoft.Playwright.NUnit
dotnet build
pwsh bin/Debug/net8.0/playwright.ps1 install     # download browsers (adjust the net8.0 folder to your target framework)

# Library only, for scripting:
dotnet add package Microsoft.Playwright
```

The browser install script is generated by the build, so run `dotnet build` first. It requires PowerShell (`pwsh`).

## Four core concepts: locate, act, wait, assert

### 1. Locate — `page.Locator(...)`

A `Locator` is a lazy handle that re-queries the DOM on every use.

```csharp
page.Locator("#id-example-1");                                  // id
page.Locator("[name='name-example-1']");                        // attribute
page.Locator(".class-example-1");                               // class
page.Locator("a", new() { HasTextString = "Link Example 1" });  // text
page.Locator("xpath=//input[@type='submit']");                  // XPath
```

Prefer user-facing locators where they fit: `page.GetByRole(AriaRole.Button, new() { Name = "Submit" })`, `page.GetByLabel("Text Example 1")`, `page.GetByText("Id Example 1")`.

### 2. Act — `ILocator` methods

`ClickAsync()`, `FillAsync(value)`, `CheckAsync()`, `UncheckAsync()`, `SelectOptionAsync(...)`, `TextContentAsync()`, `InputValueAsync()`, `GetAttributeAsync(name)`. All are `Task`-returning and must be `await`ed.

### 3. Wait — auto-waiting

Before `ClickAsync`, `FillAsync`, `CheckAsync`, etc., Playwright automatically waits for the element to be attached, visible, stable, enabled, and receiving events. You do **not** write polling loops or `Task.Delay`. Use `locator.WaitForAsync()` or `page.WaitForURLAsync(...)` only for conditions outside the standard actionability checks.

### 4. Assert — see "From walkthrough to real test" below.

## Full worked example

A walkthrough against the free fixture page https://testingexamples.github.io (top-level statements, .NET 6+):

```csharp
using Microsoft.Playwright;

using var playwright = await Playwright.CreateAsync();
await using var browser = await playwright.Chromium.LaunchAsync(new() { Headless = false });
var context = await browser.NewContextAsync();
var page = await context.NewPageAsync();

await page.GotoAsync("https://testingexamples.github.io");

// Locate by id, name, class, link text, and XPath.
Console.WriteLine(await page.Locator("#id-example-1").EvaluateAsync<string>("el => el.outerHTML"));
Console.WriteLine(await page.Locator("[name='name-example-1']").EvaluateAsync<string>("el => el.outerHTML"));
Console.WriteLine(await page.Locator(".class-example-1").EvaluateAsync<string>("el => el.outerHTML"));
Console.WriteLine(await page.Locator("a", new() { HasTextString = "Link Example 1" })
    .EvaluateAsync<string>("el => el.outerHTML"));
Console.WriteLine(await page.Locator("xpath=//input[@type='submit']").EvaluateAsync<string>("el => el.outerHTML"));

// Fill a text input.
await page.Locator("#text-example-1-id").FillAsync("hello");

// Check a checkbox and a radio button.
await page.Locator("#checkbox-example-1-id").CheckAsync();
await page.Locator("#radio-example-1-option-1-id").CheckAsync();

// Select an option by index.
var select = page.Locator("#select-example-1-id");
await select.SelectOptionAsync(new SelectOptionValue { Index = 0 });
Console.WriteLine($"Selected option value: {await select.InputValueAsync()}");
```

`using var playwright` and `await using var browser` dispose everything even if an exception is thrown. The script asserts nothing — it is a walkthrough, not a test.

## From walkthrough to real test

A **real test** derives from `PageTest` (from `Microsoft.Playwright.NUnit`) and uses `Expect(...)` — **web-first assertions** that auto-retry until the condition holds or a timeout elapses:

```csharp
using Microsoft.Playwright;
using Microsoft.Playwright.NUnit;
using NUnit.Framework;

namespace PlaywrightTests;

[TestFixture]
public class FixtureTests : PageTest
{
    [SetUp]
    public async Task GoToFixturePage()
    {
        await Page.GotoAsync("https://testingexamples.github.io");
    }

    [Test]
    public async Task IdExampleHasExpectedText()
    {
        await Expect(Page.Locator("#id-example-1")).ToHaveTextAsync("Id Example 1");
    }

    [Test]
    public async Task CheckboxCanBeChecked()
    {
        await Page.Locator("#checkbox-example-1-id").CheckAsync();
        await Expect(Page.Locator("#checkbox-example-1-id")).ToBeCheckedAsync();
    }
}
```

Why this matters:

- `PageTest` injects a fresh `Page` (and `Context`, `Browser`) per test and tears it down automatically — no manual disposal.
- `ToHaveTextAsync`, `ToBeVisibleAsync`, `ToHaveValueAsync`, `ToHaveCountAsync`, `ToBeCheckedAsync` re-check the live page until they pass or time out. A plain `Assert.That(await locator.TextContentAsync(), ...)` reads once and does not retry.
- Run with `dotnet test`. Pick the browser with `dotnet test -- Playwright.BrowserName=firefox`, or run headed with the `HEADED=1` environment variable.

## Common pitfalls

- **Forgetting `await`.** An un-awaited `ClickAsync()` compiles (with a compiler warning, CS4014) and races ahead. Treat that warning as an error. Test methods must be `async Task`, never `async void`.
- **Blocking on tasks with `.Result` / `.Wait()`.** Risks deadlocks and hides exceptions; always `await`.
- **Running tests before installing browsers.** Build, then run the `playwright.ps1 install` script, or tests fail with "Executable doesn't exist".
- **Strict-mode violations.** If a locator matches several elements, actions throw. Narrow the locator, or call `.First` / `.Nth(i)` / `.Filter(...)` deliberately.
- **Wrong `Expect` source.** Use `Expect(...)` from `PageTest` (or `Assertions.Expect`) for web-first assertions, not NUnit's `Assert`, for anything that may still be changing.
- **Using `Task.Delay` / `Thread.Sleep`.** Never needed for actionability; rely on auto-waiting and web-first assertions.
